Programming Principles

Single Responsibility Principle (SRP): Кожен клас має лише одну відповідальність. Наприклад, клас CashDispenser відповідає виключно за алгоритм видачі купюр, а TransactionLogger — лише за запис історії в БД.

Open/Closed Principle (OCP): Система відкрита для розширення, але закрита для змін. Додавання нового типу транзакцій (наприклад, "Оплата комуналки") реалізується додаванням нового класу, а не зміною існуючого коду.

Dependency Inversion Principle (DIP): Класи високого рівня (логіка банкомата) залежать від абстракцій (інтерфейсів бази даних), а не від конкретних реалізацій MySQL чи файлової системи.

DRY (Don't Repeat Yourself): Спільна логіка валідації вводу винесена в окремі helper-класи.

KISS (Keep It Simple, Stupid): Відмова від надмірно складних конструкцій там, де можна використати зрозумілий і лінійний код.

Design Patterns

State (Стан): [Посилання на папку з патерном]. Банкомат постійно змінює свій стан: IdleState (очікує картку), AuthState (очікує PIN), TransactionState (вибір операції), OutOfMoneyState (немає готівки). Патерн дозволяє уникнути гігантських switch-case.

Observer (Спостерігач): [Посилання на файл]. Використаний для реалізації подієвої моделі (через делегати). Коли відбувається переказ коштів або зняття готівки, система генерує подію, на яку підписані TransactionLogger

Strategy (Стратегія): [Посилання на файл]. Використана для алгоритму видачі купюр. Наприклад, DefaultDispenseStrategy видає мінімальну кількість купюр (крупними), а SmallBillsDispenseStrategy — дрібними купюрами за бажанням клієнта.

Refactoring Techniques

Extract Method (Відокремлення методу): Великі шматки логіки (наприклад, алгоритм підрахунку купюр) були винесені в окремі приватні методи для кращої читабельності.

Rename Method / Variable: Зміна назв змінних з x або val на зрозумілі withdrawalAmount чи currentBalance.

Replace Magic Number with Symbolic Constant: Заміна "захардкоджених" чисел (наприклад, 3 спроби вводу PIN-коду) на константи на зразок MAX_PIN_ATTEMPTS.

Extract Class: Логіка роботи з логами та базою даних була винесена з головного класу банкомата в окремі класи DatabaseManager та Logger.

Introduce Parameter Object: Замість того, щоб передавати 5 різних параметрів у метод створення транзакції (картка, сума, дата, тип, отримувач), було створено об'єкт TransactionDetails, який передається одним параметром.
